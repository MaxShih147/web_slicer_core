Three Shims →
One Core

嚴格對照 prusa-slicer.exe、prusa-gcodeviewer.exe、 prusa-slicer-console.exe：用途差異、PE／原始碼證據、核心同源，以及 web_slicer_core 管線是「建置就不編 GUI／viewer」還是「打包再過濾」。 正式包 console 線已改名為 slicer-engine.exe。

2026-07-20 proof pack OpenSpec backend-slicer-engine-deidentification dumpbin + CMake + source build only console
00

一句話結論

先給可驗收命題，下方各節為證據。

GUI prusa-slicer.exe

完整桌面 slicer 啟動器。Subsystem = Windows GUI。不強制預覽模式。

VIEWER prusa-gcodeviewer.exe

同一 GUI 家族；編譯時寫死插入 --gcodeviewer，預設只開 G-code 預覽器模式。

CLI prusa-slicer-console.exe

命令列啟動器。Subsystem = Windows CUI。正式包改名為 slicer-engine.exe。

核心功能：三者不是三套切片引擎。皆為小啟動器 → 載入同一顆核心 DLL → 呼叫同一個入口。差異在啟動殼（GUI／CUI）與是否強制 --gcodeviewer 模式。

管線：正式建置不是「三個都編完再打包刪」。 官方腳本只編 PrusaSlicer_app_console → slicer-engine.exe； GUI／viewer 預設不編譯；打包再 SKIP 品牌殘留當保險。詳見 §08。

嚴格差異矩陣

可用「Subsystem + 是否內嵌 --gcodeviewer」唯一判別三者。

判準 prusa-slicer.exe prusa-gcodeviewer.exe prusa-slicer-console.exe
CMake target PrusaSlicer_app_gui PrusaSlicer_app_gcodeviewer PrusaSlicer_app_console
OUTPUT_NAME prusa-slicer prusa-gcodeviewer 舊 console → 現 slicer-engine
CMake 連結型態 WIN32（GUI） WIN32（GUI） 非 WIN32（console）
編譯巨集 SLIC3R_WRAPPER_NOCONSOLE NOCONSOLE + GCODEVIEWER SLIC3R_WRAPPER_CONSOLE
進入點 wWinMain wWinMain wmain
插入 --gcodeviewer 否 是（編譯期寫死） 否
產品用途 完整桌面 UI（擺模／切片／調參） 只開 G-code 預覽器模式 CLI／腳本／agent 自動化
判別式：subsystem=GUI ∧ ¬gcodeviewer → slicer UI
判別式：subsystem=GUI ∧ gcodeviewer → viewer 模式
判別式：subsystem=CUI → console / slicer-engine

03

CMake 建置定義證據

檔案：web_slicer_core/third_party/prusaslicer_fork/src/CMakeLists.txt

# GUI — 完整桌面
add_executable(PrusaSlicer_app_gui WIN32 PrusaSlicer_app_msvc.cpp ...)
target_compile_definitions(... SLIC3R_WRAPPER_NOCONSOLE)
set_target_properties(... OUTPUT_NAME "prusa-slicer")
add_dependencies(... PrusaSlicer)   # 同一核心 DLL target

# Console — CLI（正式包 OUTPUT_NAME 已改）
add_executable(PrusaSlicer_app_console PrusaSlicer_app_msvc.cpp ...)
target_compile_definitions(... SLIC3R_WRAPPER_CONSOLE)
set_target_properties(... OUTPUT_NAME "slicer-engine")
add_dependencies(... PrusaSlicer)

# G-code viewer — GUI + 強制模式
add_executable(PrusaSlicer_app_gcodeviewer WIN32 PrusaSlicer_app_msvc.cpp ...)
target_compile_definitions(... NOCONSOLE + SLIC3R_WRAPPER_GCODEVIEWER)
set_target_properties(... OUTPUT_NAME "prusa-gcodeviewer")
add_dependencies(... PrusaSlicer)
三個 target 都編譯同一份 PrusaSlicer_app_msvc.cpp，都 add_dependencies(... PrusaSlicer)。 這是「同源啟動器、同一核心」的建置級證明。
04

啟動器原始碼證據

檔案：PrusaSlicer_app_msvc.cpp

// 進入點：GUI／viewer 用 wWinMain；console 用 wmain
#ifdef SLIC3R_WRAPPER_NOCONSOLE
int APIENTRY wWinMain(...) { ... }
#else
int wmain(...) { ... }
#endif

// 只有 gcodeviewer target 會編譯進這段 → 「自動加參數」的精確定義
#ifdef SLIC3R_WRAPPER_GCODEVIEWER
    wchar_t gcodeviewer_param[] = L"--gcodeviewer";
    argv_extended.emplace_back(gcodeviewer_param);
#endif

// 三個 shim 共用：載入同一 DLL、同一入口、把 argv 交出去
wcscat(path_to_slic3r, L"slicer_core.dll");          // 舊包為 PrusaSlicer.dll
HINSTANCE h = LoadLibraryExW(path_to_slic3r, ...);
slic3r_main = GetProcAddress(h, "slicer_run_cli");   // 舊包為 slic3r_main
return slic3r_main(argc, argv_extended.data());
05

核心功能無差異 — 證明鏈

命題：除 GUI／啟動模式外，沒有三套獨立切片核心。

#證據說明
A 同一 .cpp × 三 target 見 §03 CMake；殼不同、核心依賴相同
B 同一 LoadLibrary / GetProcAddress 見 §04；不依 exe 檔名選不同引擎
C PE：三 shim 皆指向 PrusaSlicer.dll + slic3r_main 見 §02 本機掃描
D 體積比 ~135KB vs ~16MB 功能質量在 DLL，不在三個 exe
E viewer 唯一增量 = --gcodeviewer PrintConfig：Visualize an already sliced and saved G-code
F 上游 Process.cpp 註解 Just run PrusaSlicer and give it a --gcodeviewer parameter. 
// libslic3r/PrintConfig.cpp — 模式開關，不是另一套引擎
def = this->add("gcodeviewer", coBool);
def->tooltip = L"Visualize an already sliced and saved G-code";
def->cli = "gcodeviewer";

// slic3r/Utils/Process.cpp — 上游自己的等價定義
// Just run PrusaSlicer and give it a --gcodeviewer parameter.
if (instance_type == GCodeViewer)
    args.emplace_back("--gcodeviewer");
等價式：prusa-gcodeviewer.exe ≡ prusa-slicer.exe --gcodeviewer
等價式：prusa-slicer-console.exe（舊） ≡ slicer-engine.exe（新，CUI console 線）

正式包保留哪一條線

政策 + PE：保留的是 console 線，並改名。

項目 舊 console 正式包
檔名 prusa-slicer-console.exe slicer-engine.exe
CMake target PrusaSlicer_app_console（同一 target，OUTPUT_NAME 改名）
Subsystem 3 Windows CUI 3 Windows CUI
核心 DLL PrusaSlicer.dll slicer_core.dll
入口 slic3r_main slicer_run_cli
本機 SHA256（前 16） D8FB9F88C032C790… 58246E2F12708C0C…
--help 字樣 — Slicer Engine … (without GUI support)
政策（windows-policy.md）：正式包單一 headless shim slicer-engine.exe，取代 prusa-slicer.exe／prusa-slicer-console.exe； prusa-gcodeviewer.exe MUST NOT 作為引擎驗收路徑。 Agent 只呼叫 SLICER_ENGINE_BIN → slicer-engine.exe。
07

「自動加 --gcodeviewer」是什麼意思

不是執行期偵測檔名；是編譯 gcodeviewer target 時用 #ifdef 把字串寫進程式。

手動加

你在命令列輸入：
prusa-slicer.exe --gcodeviewer

自動加

雙擊 prusa-gcodeviewer.exe；啟動器在呼叫核心前，自己把 --gcodeviewer 塞進 argv。

效果

核心收到相同模式開關 → 開 G-code 預覽器，而非完整編輯預設流程。

08

建置 vs 打包 — 實際管線

問題：web_slicer_core 是完全不編譯 prusa-slicer.exe／prusa-gcodeviewer.exe， 還是會編譯、打包時再過濾？答案：預設不編譯 + 打包再擋一層。

檔案／角色 官方建置腳本 打包 正式包結果
prusa-slicer-console → slicer-engine 會編（唯一 --target） 收進 bin slicer-engine.exe
prusa-slicer.exe（GUI） 不編 若出現則 SKIP 不出貨
prusa-gcodeviewer.exe 不編 若出現則 SKIP 不出貨
不是「三個都編好，打包再刪」。 是「建置階段就只做 console；打包過濾是防舊檔／手動誤編」。 Program Files／舊 unpack 裡的 prusaslicer_build\src\Release\prusa-*.exe 是舊全量樹殘留，不代表現行 bat 行為—— 那正是 Before／After 證據頁 Install folder §03 Before 欄會看到 prusa-slicer.exe／prusa-gcodeviewer.exe 的原因； After 的「not shipped」與此表「正式包結果＝不出貨」同一結論。

09

bin/resources 研究紀錄

路徑：slicer-engine/bin/resources · 紀錄 2026-07-20 · 含（1）runtime 必要性（2）品牌文字洩漏（3）對 agent 切片／支撐／鏤空／打洞的影響。

9.1 Runtime 必要性（dental SLA / headless）

產品路徑：slicer-engine.exe … --load <job.ini>，建置 SLIC3R_GUI=OFF。 必須保留的是 bin/resources 目錄本身（Setup.cpp 寫死 exe_dir/resources）； 底下內容幾乎都不是這條 SLA 路徑所需要的。

資料夾 大小約 結論
resources/（空目錄亦可） — 必須有（路徑契約）
profiles/ ~46 MB 本產品可不需要（agent 不用系統 preset）；刪前建議 SLA smoke
fonts/ ~20 MB 可不需要（ImGui/GUI）
localization/ ~12 MB 可不需要
shapes/ ~12 MB 可不需要（內建模型庫）
icons/ ~1.4 MB 可不需要
shaders/ ~0.1 MB 可不需要
web/ ~0.02 MB 可不需要（Connect WebView）
udev/ ~0 可不需要（Linux）
data/ ~0.08 MB 可不需要（hints／emboss／gantry；sla_support.svg 旗標也關）
實務建議： 高信心可砍：icons／shaders／fonts／localization／shapes／udev／web／大部分 data。 profiles/ 也可整包拿掉（約半數體積），但政策要求先跑 --export-sla／--export-support-stl（及 hollow）smoke。 現有 staging 只做檔名去品牌，還沒做內容精簡。

掃描：bin/resources（不分大小寫；含 prusa、slic3r、PrusaSlicer、prusa slicer、prusa-slicer）。

類型結果
檔名／路徑 0（stage 已濾；scan resource_brand_path_count: 0）
二進位（.mo／.png／.ttf／.obj 等） 0
文字內容 76 個檔案仍有洩漏

洩漏類型（檔案數，可重疊）：

PrusaSlicer：40
slic3r（多為 min_slic3r_version）：42
files.prusa3d.com／help URL：35
non-prusa-*：34
Prusament／Prusa Polymers：11

76 檔清單： profiles/ 70（幾乎所有 vendor .ini／.idx；含 ArchiveRepositoryManifest、Templates、Sovol、HartSmart…）— 典型：repo_id = non-prusa-*、config_update_url = https://files.prusa3d.com/.../PrusaSlicer-settings-...、 min_slic3r_version、Prusament、gcode 註解。

其他 6：data/hints.ini、data/printer_gantries/geometries.json、 localization/list.txt、localization/wx_locale/be.po、 web/connect_error.html、web/connect_loading.html（+ udev 路徑字串）。

重點：deid gate 只擋路徑品牌名，不擋檔案內容 → scan 可 PASS，但 profiles 等仍大量殘留。 內容也要清：最快是砍整包 profiles（及 web／udev／localization／data 上述檔），且對齊 headless 可不需要這些資產。

9.3 會不會影響切片／長支撐／鏤空／打洞？

對照 agent/jobs.py、agent/sla_operations.py 實際 CLI／Python 路徑。

功能 實際呼叫 依賴 bin/resources 內容？
切片（SLA） slicer-engine --export-sla [--export-support-stl] --load config.ini model.stl 不依賴 profiles／fonts／icons…（設定全來自 job INI）
長支撐 --export-support-stl --load config.ini 不依賴
鏤空 --export-hollow-stl --load … 不依賴
切割 --cut=Z --export-stl 不依賴
打洞／蜂巢 agent 內 trimesh 產生 drain／hex，再 boolean 不依賴引擎 resources
Boolean agent trimesh＋manifold3d 不依賴
結論：牙科 SLA 主路徑（切片／支撐／鏤空／打洞／切割／boolean） 不讀 profiles/ 等 bundled 資產；參數來自 agent 產生的 config.ini。 精簡／刪除這些子資料夾理論上不影響上述功能。 仍建議：保留空的 bin/resources/（路徑契約）；砍內容前跑一輪 --export-sla／--export-support-stl／--export-hollow-stl smoke。
