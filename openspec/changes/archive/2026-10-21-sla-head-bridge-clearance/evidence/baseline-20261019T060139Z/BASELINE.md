## 1.8 量測方法

```
python -I ../tools/bench_steps.py --engine <exe> --out <work> --reps 3
python -I ../tools/determinism.py --engine <exe> --out <work> --runs 4
python -I ../tools/analyze_tree.py <work>/<case>/runs/det_*/tree.json --json ...
```

- 每個案例都**匯入固定的支撐點清單**（`inputs/pts_*.json`，由同一引擎以 `inputs/config_*.ini` 匯出一次）。混合尺寸案例以 `random.seed(1..5)` 從 0.25 / 0.4 / 0.75 抽 `head_back_radius_mm`，套用在 `pts_02_e5_d400.json` 上（雜湊見 `cases/02_mixed_s*/points.sha256`）。**之後的量測請一律加上 `--inputs <本目錄>/inputs`**，前後兩版引擎才會吃到完全相同的支撐點。
- T = 第 3、4 步合計（log 中「Routing to ground」到「Interconnecting pillars」的時間戳差），3 次取中位數。log 時間戳的解析度約 1 ms。
- 被刪除的支撐頭 = log 中 `Failed to route model facing support point` 的行數（8 次執行全部記錄）。
- 確定性：多執行緒 4 次 + `--threads 1` 1 次。`head_paths` 雜湊只涵蓋第 3、4 步的產物（支撐頭、非輔助柱、`head` / `route` 桿），定義見 `determinism.py`。
- 缺陷計數以 `--threads 1` 那棵樹為準（它可重現）；括號內為 4 次多執行緒的最小～最大值，沒有括號表示 5 次都相同。間隙 0.2 mm，計數定義見 `analyze_tree.py` 開頭說明。
- `bench.json`、`determinism.json` 內的路徑指向量測當時的暫存目錄，引擎輸出（tree.json、STL）體積大，未納入版控。

## 觀察

1. **支撐點與支撐頭的不確定性在本變更範圍外，所以改用固定支撐點。** 第一次量測（同日 05:55，讓引擎自行生成支撐點）時，China-dragon1 的支撐點數在 817 與 818 之間跳動，有效支撐頭數 809～811。改為匯入固定清單後，China-dragon1 與 Pikachu 的支撐頭（不含 `pillar` 欄位）在 5 次執行中逐位元相同，剩下的差異全部來自第 3 步之後。之後 3.13 的確定性門檻必須在同一份固定清單上判定，否則不可能通過。
2. **掛橋路徑的不確定性確實存在，是本變更要消除的部分。** China-dragon1 與 Pikachu 的 `head_paths` 5 次各不相同，`--threads 1` 也和 4 次多執行緒都不同。02 各案例在固定支撐點下 5 次相同，但第一次量測（自行生成支撐點）時 02 的三組非混合案例各出現 2 種掛橋路徑，可見 02 也不保證可重現，只是這 5 次剛好一致。
3. **重複柱對在基準線已為 0。** 探索期在 `release/v1.0.6`（未合 planar）上看到的柱 35↔94 重複 8 根，合入 planar 後的 02_e5_d100 已不再出現。幾何完全相同的重複桿與 `pairs` 超額（幾何不同的第二組）在所有案例的 5 次執行中都是 0。5.2 的 `duplicate_pair` 仍照規格實作，作為防護；5.8「重複柱對 = 0」在基準線就已成立。
4. **B 中有相當比例屬於「共用柱但碰撞在 R 外」**（planar 目前整根豁免的那一類）：02_e5_d100 的 5 處全是這一類，China-dragon1 也全是。這是 5.1 要處理的部分。
5. **D 與粗頭掛細柱只出現在混合尺寸案例**：D 每個種子 1～3 處，粗頭掛細柱 50～62 處。單一尺寸的案例都是 0。
6. **反向 C 的「柱碰支撐頭」幾乎全是支撐點原生過密。** 依 2026-10-19 裁決（方案二：驗收時排除原生過密，第 3(a) 步中心柱不進降級），扣除後的淨值每個案例只剩 0～1 處，共 4 處：
   - 02_mixed_s1 柱 62（由支撐頭 486 長出，只承載自己）碰支撐頭 473：距離 1.662，門檻 1.7。
   - 02_mixed_s2 柱 8（中心柱，承載 3 個支撐頭）碰支撐頭 386：1.666 / 1.7。
   - China-dragon1 柱 76（中心柱，承載 4 個支撐頭）碰支撐頭 432：1.159 / 1.2。
   - Pikachu 柱 442（繞路後長出的柱，第 4 步）碰支撐頭 16：0.848 / 1.2。

   Pikachu 這一處會經過降級狀態機，之後會有 L1 / L2 紀錄。另外 3 處的柱屬第 3(a) 步（或與之同型的自身地柱），差距都只有 0.03～0.04 mm、沒有實體穿透（L1 間隙下會通過）。但依裁決它們不進降級、不會留下紀錄，而且不屬於原生過密，所以照現行 spec 會成為「沒有紀錄的違規」。**這 3 處的處理方式尚待裁決**（design 決策 7 寫中心柱建立時「此時沒有掛橋可被刺穿」，但沒有考慮到支撐頭在分類後就已插入索引）。
7. 02 各案例的 T 只有 1～70 ms，門檻實際上由 50 ms 決定；China-dragon1 與 Pikachu 的 T 才是 10% 門檻真正起作用的案例。
