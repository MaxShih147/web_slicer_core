# 底墊全域參數開放（F2）— 改動說明

## 本次更新

**本次只開放後端 API，不做前端面板。** 使用者要在面板上實際調整，得等前端
人員依 `api/slicing_core.md` 契約另外接上 UI 之後才行。以下描述的是 API 層面
的能力，不是這次就能在畫面上看到的效果：

- **底墊全域參數**：後端 `SLAConfig` 原本只宣告 `pad_enable` 一個底墊開關；
  本次額外開放 11 個底墊參數（底墊厚度、空腔深度、外擴尺寸、合併距離、側壁
  斜度、環繞物件底墊、強制全面環繞、物件間隙、連接柱間距／寬度／侵入深度）
  的 API 欄位，前端接上後使用者才能自行調整，不再只能用引擎內建的固定值。
- **底墊側壁斜度**：這是本次唯一有範圍限制的欄位，只接受 45 到 90 度。送出
  範圍外的值（例如 0）會被系統擋下並回傳錯誤。原因是引擎內部用這個角度做除法
  計算，送 0 會造成除以零，算出來的幾何會壞掉。
- **環繞物件底墊（zero-elevation）**：這個開關打開後，引擎會忽略「物件抬升
  高度」，改成讓底墊直接包住模型底部。另外有 4 個參數（強制全面環繞、物件
  間隙、連接柱三項）只有在「底墊產生」與「環繞物件底墊」**兩個開關同時打開**
  時才會生效，其他情況引擎會直接忽略、不會報錯。這個條件會寫進契約文件，
  前端接手時再決定要隱藏還是顯示成灰階。
- **參數組合的限制**：引擎本身有兩條檢查規則——底墊外擴太小配上太厚的牆會被
  拒絕；環繞物件模式下，「底座安全距離」必須大於「底墊物件間隙」。這兩條
  本次不在 API 層先擋，維持送給引擎、由引擎回報的做法，但會把規則寫進契約
  文件，前端可以先在畫面上提示使用者。

## 工作計畫

這批參數其實切片引擎本來就會讀，只是我們的後端還沒把這些欄位「打通」讓
使用者調整——引擎那邊完全不用改。做法與上一輪的 F1（支撐樹全域參數）相同，
**本次範圍只做後端＋API 契約文件，不含前端面板**，分兩層：

1. **後端**：在設定資料結構裡補上這 11 個欄位，讓使用者送出的值可以正確傳給
   引擎。其中 1 個需要多做驗證：
   - 「底墊側壁斜度」只接受 45 到 90 度，填錯會被系統擋下並告知錯誤，而不是
     讓切片默默算出壞掉的幾何。
   - 另外要注意一個陷阱：引擎裡有兩套底墊預設值，數字對不上（例如底墊厚度
     一邊寫 2mm、一邊寫 1mm）。本次採用實際會生效的那一套，並在程式碼裡註記，
     避免日後有人「照另一套修正」而改錯。
2. **文件**：更新後端 API 的說明文件，讓前端人員之後可以依這份契約自行開發
   串接到面板，不用等這次一起做。

前端面板（滑桿、輸入框、開關、四種語言文案）留到之後由前端人員另外排一個
change 處理。前端目前有一個寫死的底墊厚度常數（2mm），要換成讀真值，也屬於
前端範圍。

完工後會額外發布一份說明頁面（Artifact），把這次「哪些參數怎麼分類、為什麼
只擋一個、預設值陷阱在哪、還有哪些可以往後延伸開發」都記下來。

## 參數表（Parameter Table）

| 參數名稱 | 說明 | 預設值 | 範圍/選項 | 影響 |
|---|---|---|---|---|
| 底墊厚度 | 底墊本體與空腔牆的厚度 | 2.0mm | 0–30mm | 底墊強度；也決定手動編輯器裡模型被抬多高 |
| 底墊空腔深度 | 底墊內部挖空的深度 | 0mm（關閉） | 0–30mm | **注意**：某些樹脂會在空腔內產生吸附效應，離型困難 |
| 底墊外擴 | 底墊比模型輪廓多向外延伸多少 | 1.6mm | 0–30mm | 底墊附著面積 |
| 底墊合併距離 | 兩塊小底墊多近會被合併成一塊 | 50mm | 0mm 以上 | 底墊數量與分布 |
| 底墊側壁斜度 | 底墊側壁與底板的夾角，90 度為垂直 | 90° | **45–90°**（超出範圍會被擋下） | 底墊側壁造型 |
| 環繞物件底墊 | 底墊改為直接包住模型底部 | 關閉 | 開／關 | 開啟後引擎忽略「物件抬升高度」 |
| 強制全面環繞 | 強制底墊在所有位置都環繞 | 關閉 | 開／關 | 只在「環繞物件底墊」開啟時生效 |
| 底墊物件間隙 | 模型底部與底墊之間留多少空隙 | 1mm | 0–10mm | 只在「環繞物件底墊」開啟時生效 |
| 連接柱間距 | 連接模型與底墊的小柱子，每隔多遠放一根 | 10mm | 0mm 以上（0＝不產生） | 只在「環繞物件底墊」開啟時生效 |
| 連接柱寬度 | 小柱子的寬度 | 0.5mm | 0mm 以上（0＝不產生） | 只在「環繞物件底墊」開啟時生效 |
| 連接柱侵入深度 | 小柱子插進模型多深 | 0.3mm | 0mm 以上 | 只在「環繞物件底墊」開啟時生效 |

| 變更類型 | Method | Endpoint | 說明 | Request | Response |
|---|---|---|---|---|---|
| 修改 | （既有切片相關 endpoint，見 `api/slicing_core.md`） | 切片設定 request body | request body 新增上述 11 個參數欄位 | body 新增 11 個欄位（皆有預設值，可選填） | `pad_wall_slope` 填 45–90 以外的值回傳驗證錯誤，其餘不變 |

## 驗收方式（Acceptance）

本次不含前端面板，驗收改成直接呼叫後端 API（不透過 UI）：

1. **11 個參數可送可調**：直接呼叫切片 API，逐一帶入自訂值，確認回應正常、
   `config.ini` 內容與送出值一致，且生成的底墊幾何隨參數值變化。
2. **側壁斜度範圍**：送 `45`／`67.5`／`90` 可正常設定；送 `0`／`120`／負值
   回傳驗證錯誤且不呼叫引擎。
3. **預設值正確**：完全不送這批欄位時，切片結果與加欄位前完全一致（證明
   預設值取的是實際生效的那一套）。
4. **環繞物件底墊條件**：兩個開關沒同時打開時，送出那 4 個專屬參數不會報錯，
   引擎直接忽略；兩個都打開時，參數確實影響幾何。
5. **連接柱設 0**：`pad_object_connector_stride=0` 時切片成功完成，不產生
   連接柱，不報錯。
6. **交叉驗證透傳**：`pad_brim_size` 設成極小值（例如 0.05）時，API 接受並
   送出，引擎在切片階段回報「底墊外擴太小」的錯誤訊息。
7. **API 文件**：打開 `api/slicing_core.md`，確認能查到這 11 個新參數的說明，
   以及兩條引擎交叉驗證規則，前端人員光看這份文件就能知道怎麼串接。

面板 UI 驗收（拖動滑桿看預覽、開關連動顯示、tooltip 文案等）留給前端 change
處理時另行驗收。

## 已知的待追蹤項目（不影響本次驗收）

引擎在切片階段檢查參數組合失敗時，錯誤訊息回傳的可靠性，在「整盤切片」這條
路徑上還沒有人驗證過。這件事由本次開放參數所引發（在此之前使用者送不出會
觸發檢查失敗的組合），但成因是既有的錯誤處理設計，不是本次新增的問題。
已確認**獨立追蹤、不擋本次完工**，會另外整理成一份查證清單，查完再決定要不要
另開一輪工作補強。
